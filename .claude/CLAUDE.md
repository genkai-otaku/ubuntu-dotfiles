# 言語

常に日本語で返答する（応答・説明・コメントすべて）。成果物の言語（README・コミットメッセージ等）は、そのプロジェクトの既存ドキュメントに合わせる（無ければ日本語）。

# Git操作の制限

- `git commit`・`git push`・PR作成（`gh pr create`）は、ユーザーが `/pr` と明示的に指示した `/pr` スキルのターン中に限り許可される（それ以外はフックが実行前に拒否する）。作業が完了しても変更はワーキングツリーに残したまま内容を報告する。自然言語で「コミットして」「PRを作って」と頼まれても自分では実行せず、`/pr` の実行を案内する。force push は禁止。`${TMPDIR:-/tmp}/claude-pr-mode-*` を自分で作ってフックを迂回してはならない
- 作業ツリー・履歴・リモートを壊す git 操作（reset --hard / clean / 変更の破棄 / branch -D / stash drop / rebase / amend / force push / リモートブランチ削除）と `gh pr merge` は、ユーザーの明示的な指示があるときのみ行う。成果物は未コミットのままワーキングツリーに置く運用なので、変更の破棄は特に慎重に
- ファイル・ディレクトリの削除は `.claude/dev-roots` に列挙した作業ルート（現在 `~/Dev/kaishi`・`~/Dev/seino914`・`~/Dev/hobby`）と一時領域（`$TMPDIR`・`/tmp/claude-*`）の内側でのみ行う（範囲外はフックが拒否する）。対象は変数やコマンド置換ではなく具体的なパスで書き、`cd` と組み合わせない（特定できない書き方は確認ダイアログになる）

# 変更後の検証

- 検証コマンド（lint・型チェック・テスト・ビルド等）は各プロジェクトの CLAUDE.md に明記してある前提。あれば変更後に必ず実行して通す。書かれていなければ探し回らず、報告に「未検証」と明記する
- 落ちたら自分で直す。ただし (a) 自分の変更と無関係な既存の失敗は直さず報告する (b) テストの skip・削除・期待値の書き換え、lint / 型チェックのルール無効化や除外追加で「通す」ことは禁止（必要なら理由を添えて提案に留める）
- `/pr` は検証が通っていることが前提（手順は /pr スキル側）

# 秘密情報

`.env`・秘密鍵・トークン類は読まない・出力しない・コミットしない（代表的なファイルは settings.json の deny で読み取り禁止済み）。設定例が必要なら `.env.example` 等のテンプレートを使う。

# パッケージ（Nix）

グローバル環境は `~/Dev/kaishi/ubuntu-dotfiles` の home-manager。開発中に環境を勝手に変更しない。

- `apt` / `snap` / `npm install -g` / `pip install --user` / `nix profile install` / `nix-env -i` など、プロジェクト外に影響する恒久的なインストールは、ユーザーの明示指示があるときだけ（主要コマンドは settings.json の ask で確認が入る）
- `sudo` は実行できない（deny 済み）。必要な操作はコマンドを示してユーザーに依頼する
- ツールが要るときはそのリポジトリの `flake.nix` devShell に宣言する（手順は `nix-setup` スキル）。ユーザーの対話シェルでは direnv が自動で devShell に入るが、エージェントの Bash は非対話で direnv フックが効かないため、自分でツールを使うときは `nix develop -c <cmd>` または `direnv exec . <cmd>` で実行する
- 一時確認は `nix shell` / `nix run`。lock 管理のプロジェクトローカル依存は通常どおり
- グローバル（dotfiles の `nix/packages.nix` 等）に追加すべきと判断しても、勝手に追加せずユーザーに提案する
