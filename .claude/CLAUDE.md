# Git操作の制限

`git commit`・`git push`・PR作成（`gh pr create`）は、ユーザーが `/pr` と打った `/pr` スキル実行中に限り許可される。「PRを出して」は `/pr` ではない。force push は禁止。`${TMPDIR:-/tmp}/claude-pr-mode-*` を自分で作ってフックを迂回してはならない。作業完了後も勝手にコミットせず、変更はワーキングツリーに残して報告する。

# 変更後の検証

プロジェクトに lint・型チェック・テスト・ビルドがあれば変更後に通す。落ちたら自分で直す（無関係な既存失敗は直さず報告）。`/pr` の前は必ず通す。

# パッケージ（Nix）

グローバル環境は `~/Dev/kaishi/ubuntu-dotfiles` の home-manager。`apt` / `snap` / `npm install -g` / `pip install --user` はユーザーの明示指示があるときだけ。ツールが要るときはそのリポジトリの `flake.nix` devShell に宣言する（手順は `nix-setup` スキル）。一時確認は `nix shell` / `nix run`。lock 管理のプロジェクトローカル依存は通常どおり。グローバル追加は提案のみ。

# サブエージェント

調査・実装はサブエージェントへ切り出し、指示は自己完結（対象・制約・完了条件）。独立タスクは並列。成果物は親がレビューしてから完了。自明な局所修正と、設計と実装が不可分な箇所は親がやってよい。モデルの振り分けは各ハーネス側（Claude は `~/.claude/rules/`、Grok は `~/.grok/AGENTS.md`）。
