# モデル運用（Claude Code）

メインセッション向け。委譲の原則は `~/.claude/CLAUDE.md` の「サブエージェント」。モデルは Agent ツールの `model` で選ぶ（未指定なら `settings.json` の `CLAUDE_CODE_SUBAGENT_MODEL` = opus）。

- **opus**：実装・テスト作成・複数ファイルの修正・不具合の原因調査・設計に関わるリファクタ
- **sonnet**：仕様と完了条件が固まった小〜中規模の作業（既存パターンに沿った追加、1〜2ファイルの変更、ドキュメント更新、機械的なリファクタ、複数ファイルを読む調査・要約、公式ドキュメントの調べもの）
- **haiku**：所在の特定・検索・単純な事実確認・出力の要約（Explore は `agents/Explore.md` で haiku 固定。難しい探索は `model: "sonnet"` を渡す）
- **fable**：Opus の手に余るものだけ。(a) 文脈が揃っていて Opus が同じ問題で2回続けて誤った (b) 誤りのコストが高く判定が繊細な設計・実装（外部入力に晒されるセキュリティ境界・並行処理・データ移行など。事故防止の部品は含まない） (c) 長く多段の課題を1エージェントに任せるとき

運用：

- モデルを上げる前に失敗の原因を見る。見落とし・検証漏れ・指示不足なら指示を直して同じモデルで出し直し、文脈が揃っていて誤ったときだけ上げる（sonnet / haiku → opus → fable）
- 独立レビューは実装と別のモデルで行う（同じモデルは同じ見落としをする）。opus の実装（メインの直接実装を含む）は fable、fable の実装は opus、sonnet / haiku の実装は opus がレビューする
- 外部入力に晒されるセキュリティ境界は opus と fable の2本を並列で独立にレビューさせ、食い違ったらメインが再現経路で判断する（決めきれなければユーザーに確認）

# フックの挙動（Claude Code）

実体は dotfiles の `.claude/hooks/`。

- `pr-mode.sh`：`/pr` 外では commit / push / PR の作成と更新を拒否する。`/pr` 中は単一コマンドだけ自動承認し、サブエージェントからの実行は拒否する。`${TMPDIR:-/tmp}/claude-pr-mode-*` を自分で作って迂回してはならない
- `guard-destructive.sh`：範囲外の削除・破壊的な git 操作・名前指定の一括プロセス終了を拒否または確認にする。拒否パターンを増やして抜け道を塞ぎ続けない
- `verify-gate.sh`：dotfiles の検証対象を編集したセッションでは、検証コマンドが成功するまでターンを終えさせない（バックグラウンド実行では解除されないのでフォアグラウンドで実行する）
